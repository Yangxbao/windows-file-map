# 本机文件地图与一键清理助手

> 只读、离线、带中文解释的本机文件全量盘点工具 + 白名单安全一键清理。
> 它把整台 Windows 电脑的文件系统扫进一个本地 SQLite 数据库，用中文网页分页浏览、
> 搜索、识别开发项目、分析空间占用；并提供「一键清理垃圾」——只清理明确安全、
> 可自动重建的临时文件与缓存。**全程不修改、不移动你的任何原始文件。**

## 功能总览

### 🗺️ 文件地图（只读盘点）
- **全量递归盘点**：所有本地固定磁盘逐级枚举到最深一层，无条目数 / 深度 / 总量上限；
- **SQLite 存储 + 服务端分页**：数百万条目流畅浏览；
- **中文解释层**：内置目录/文件知识库，结合路径、内容类型与项目标识给出用途解释与置信度；
- **项目识别**：pom.xml / package.json / go.mod / *.sln / .git / README 等（绝不运行项目代码）；
- **断点续扫 / 增量扫描 / 管理员定向重试**；
- **网页五页视图**：电脑总览 / 目录树 / 项目地图 / 全局搜索 / 空间与风险。

### 🧹 一键清理（白名单安全清理 · v4）

- 首次使用一次性确认清理范围，之后**一次点击完成扫描 + 过滤 + 清理 + 报告**；
- 打开页面即自动做一次**只读预估**，先告诉你"能释放多少"，再让你决定要不要删；
- **分类可选**：七类规则可单独勾选，每类都写明"删了会有什么影响"；
- **完成标志持久化**：清理结束后页面顶部固定显示"✅ 清理完成 / 释放了多少 / 用时 / 磁盘可用空间变化"，
  刷新页面、关掉浏览器再打开都还在（结果写入数据库，不依赖内存）；
- **实时进度**：进度条 + 当前类别 + 已处理/总数 + 已释放 + 预计剩余时间，可随时停止；
- 被占用 / 只读 / 权限不足 / 符号链接 / 目录内有新文件的对象一律跳过并**分类记录原因**
  （"正在被程序使用"属正常，不是故障）；
- 每个被删除的文件写入本地日志，网页内可分页、按结果筛选、**导出 CSV**（Excel 可直接打开）；
- 记录清理前后**磁盘可用空间**，与"文件字节数"对照，避免把簇大小差异误读成清理失败；
- 支持 `clean_excludes.txt` **排除名单**（只能本地编辑，网页端无任何写入入口）；
- 没有可清理内容时明确提示，绝不为了效果强行删除；
- 开发缓存（npm/Maven/Gradle 等）、浏览器数据、回收站等**默认不在清理范围**。

### 默认清理范围（七类，全部可自动重建）

| 类别 | 位置 | 规则 | 删除影响 |
|---|---|---|---|
| 用户临时文件 | `%TEMP%` | 超过 24 小时未修改的条目；跳过占用/链接 | 无（程序会重建） |
| Windows 临时文件 | `C:\Windows\Temp` | 同上；权限不足的部分如实跳过 | 无 |
| 缩略图与图标缓存 | `...\Explorer\thumbcache_*.db`、`iconcache_*.db` | 资源管理器占用时跳过 | 缩略图/图标短暂重建 |
| DirectX 着色器缓存 | `%LOCALAPPDATA%\D3DSCache` | 自动重建 | 游戏首启稍慢 |
| NVIDIA 着色器缓存 | `%LOCALAPPDATA%\NVIDIA\DXCache、GLCache` | 自动重建 | 游戏首启稍慢 |
| 应用崩溃转储 | `%LOCALAPPDATA%\CrashDumps\*.dmp` | 超过 24 小时 | 无（排查崩溃前请自行保留） |
| Windows 错误报告 | `...\WER\ReportQueue/Archive` | 超过 7 天 | 无 |

**明确不会清理**：个人目录、任何项目与仓库、`.git`/`.env`/`node_modules`/`target`/`build`/`dist`、
浏览器数据、回收站、Windows Installer、系统组件、注册表、分页/休眠文件、开发缓存、
以及一切无法确认用途的文件。

## 快速开始

环境要求：Windows 10/11，Python 3.8+（仅标准库，无需安装任何依赖）。

```bat
:: 1. 全量扫描（只读，首次约几分钟）
fm_scan.py

:: 2. 打开中文地图（本地服务 + 自动打开浏览器）
启动文件地图.bat

:: 3. 在页面「🧹 一键清理」中，首次确认清理范围后即可一键清理
```

| 命令 | 用途 |
|---|---|
| `python fm_scan.py` | 全量扫描（重建数据库） |
| `python fm_scan.py --resume` | 续扫上次中断的扫描 |
| `python fm_scan.py --incremental` | 增量扫描（跳过未变化目录） |
| `python fm_scan.py --admin-retry` | 管理员终端运行：定向重试历史"拒绝访问"目录（只读） |
| `python fm_scan.py --recompute` | 仅重算大小统计并重新生成报告 |
| `python fm_report.py` | 单独重新生成报告 |
| `python fm_sandbox_test.py` | 运行清理模块沙盒测试（隔离环境，不触碰真实文件） |
| `python serve.py` | 启动本地网页服务（127.0.0.1:8618） |

## 安全设计（清理模块）

- **白名单硬编码**：清理规则只存在于 `fm_clean.py` 中；前端只能传规则 ID，
  任何路径/命令参数都会被后端直接拒绝（400）；
- **双重路径校验**：每个候选在删除前再次验证位于授权根目录内；
- **不跟随链接**：符号链接与目录联接既不进入也不删除；
- **目录新鲜度保护**：目录自身时间戳很旧、但里面存在"24 小时内修改过"的文件时整目录跳过
  （避免删掉正在被程序写入的临时目录）；
- **不改属性、不提权**：只读文件直接跳过，绝不 `chmod`；权限不足只记录，绝不 `takeown`；
- **来源校验**：清理接口校验 Host/Origin，仅接受本机页面（127.0.0.1）的请求；
- **策略门禁**：未在页面确认启用安全清理前，清理接口拒绝执行；
- **可取消**：清理过程中可随时取消，取消后不再开始新的删除；
- **完整日志**：`fmdata.db` 的 `clean_runs` / `clean_log` 表记录每次运行与每个文件；
- **异常不吞**：服务端任何内部异常都返回 JSON 错误信息，不会出现"页面无反应/加载失败"。

## 架构

```
fm_scan.py   只读扫描引擎：递归枚举 + 错误分类 + 项目识别 → fmdata.db (SQLite, WAL)
fm_kb.py     共享知识库：目录/文件中文名映射、项目标识规则
fm_clean.py  安全清理引擎 v4：白名单规则 + 双重校验 + 批量日志 + 进度/原因分类 + 结果持久化
fm_report.py 报告生成：全量 CSV 分卷、扫描范围与遗漏、项目识别、整理建议
serve.py     本地服务：静态页面 + 分页 API + 清理 API（Host/Origin 校验）
index.html   中文单页应用：总览/一键清理/目录树/项目地图/搜索/空间与风险
```

清理相关接口：

| 接口 | 说明 |
|---|---|
| `GET /api/clean/categories` | 七类规则、默认勾选、永不清理清单、策略状态 |
| `POST /api/clean/scan` | 只读预览（仅接受类别 ID） |
| `POST /api/clean/run` | 执行清理（需已确认策略） |
| `POST /api/clean/cancel` | 停止后续删除 |
| `GET /api/clean/status` | 实时进度（纯内存，不查库） |
| `GET /api/clean/last` | 上次清理结果（含逐类明细、原因统计、磁盘变化） |
| `GET /api/clean/history?offset=&limit=` | 清理记录分页 |
| `GET /api/clean/log?run_id=&offset=&limit=&status=` | 逐文件日志分页 + 筛选 |
| `GET /api/clean/log.csv?run_id=` | 导出 CSV（UTF-8 BOM，Excel 直接打开） |
| `GET /api/clean/excludes` | 排除名单现状（只读） |

## 已知边界

- 回收站内容、系统还原点、本工具目录**按明确规则排除**；
- 受 Windows 强保护的目录（如 `System32\config`、WindowsApps）普通权限无法枚举，
  工具保留失败记录，绝不假装扫描完成；
- 个别文件名含 Windows 无法编码的字符，展示时以 `?` 代替，真实文件不受影响；
- 清理模块默认不含浏览器缓存与开发缓存——它们"可重建但可能有副作用"，如需加入
  应作为独立可选类别并单独确认；
- 普通权限下 `C:\Windows\Temp` 与 WER 目录里属于 SYSTEM 的部分删不掉，会显示为"跳过/权限不足"，
  这是正常现象，本工具不会为此提权。

## 更新记录

### v4（2026-10-29）清理模块重构
- **修复**「清理记录」一直显示"加载失败"：数据库连接漏设 `row_factory`，`dict(元组)` 直接抛异常，
  服务端又只捕获 `sqlite3.Error`，异常逃逸导致连接被断开。现统一使用 `sqlite3.Row`，
  并让所有接口在任何异常下都返回 JSON 错误说明。
- **修复**清理完成后界面没有完成标志：结果只存在进程内存里。现把逐类明细、原因统计、
  磁盘变化写入 `clean_runs.detail`，新增 `/api/clean/last`，页面顶部固定显示上次结果（刷新不丢）。
- **修复**跳过/失败数在部分分支没有计入总数（会显示 0）。
- **修复** `fm_scan.py` 文档字符串里的 `\ud800` 转义会在 Python 3.12+ 编译期生成孤立代理字符，
  导致模块**根本无法导入**（本机 3.13 下 `serve.py` 直接起不来）。改为纯文本写法。
- **新增**实时进度条 + 当前类别 + 预计剩余时间；分类勾选与"删除影响"说明。
- **新增**失败原因分类（占用 / 权限不足 / 只读 / 已消失 / 其它），占用与权限不足归入"跳过"，
  界面直接解释，不再用"失败 359"吓人。
- **新增**目录新鲜度保护、长路径（`\\?\`）支持、`clean_excludes.txt` 排除名单、CSV 导出、
  旧库自动 `ALTER TABLE` 平滑升级、崩溃遗留 `running` 记录自动标记 `interrupted`。
- **性能**逐文件日志改为批量提交（每 200 条 / 1 秒），轮询接口不再每次建库连接。
